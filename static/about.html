About

A CNN that classifies brain MRI scans into four classes, served by a FastAPI backend that returns a Grad-CAM heatmap with every prediction.

01Model

Architecture and accuracy

Four Conv2D + MaxPooling blocks (64, 64, 128, 512 filters). The last block feeds global average and global max pooling in parallel, concatenated into a Dense(128) layer with 0.3 dropout and a 4-way softmax. Trained from scratch on 256×256 images.

02Pipeline

What happens to an upload

  1. Decode and resizeTensorFlow ops, the same resize used in training, so serving matches training.
  2. NormalizePixel values are scaled to the 0 to 1 range.
  3. PredictThe model, loaded once at startup, returns a confidence for each of the four classes.
  4. ExplainGrad-CAM traces gradients through the last convolutional layer and overlays the heatmap on the scan.
03Limitations

Known limitations

Meningioma is often read as glioma

93 of 400 meningioma test scans are classified as glioma. Location is the main cue separating the two, and global pooling discards it. Three fine-tuning attempts did not help. A fix likely needs an architectural change.

GPU metrics did not match CPU

The notebook reported 92.44% test accuracy on Apple's Metal GPU backend. The same weights score 88.06% on CPU, which is what Cloud Run uses. The cause is a known TensorFlow issue where Metal skips a Dense layer's ReLU in compiled-graph execution.

Scans from other sources are less reliable

The training data merges three collections, each with its own scanners and contrast conventions. Images that look different from them are classified less accurately than the test set.

04Architecture

Backend

Three modules with narrow interfaces: preprocessing (bytes to array), inference (array to prediction), and Grad-CAM (array to heatmap). The FastAPI routes wire them together and map failures to HTTP errors, so a bad upload returns a 400.

The model file is not in git. It is hosted on the Hugging Face Hub and pulled into the Docker image at build time, pinned to a commit revision.

05Deployment

Google Cloud Run

The app runs as a single container on Cloud Run with 2 GiB of memory and 2 vCPUs, and scales to zero when idle. A GitHub Actions workflow builds the image, pushes it to Artifact Registry, and deploys a new revision on every push to main.
